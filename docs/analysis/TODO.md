Chat AI 自动回复 — 方案设计

  当前已有的能力

  Email 模式 (已完整实现):
    客户发邮件 → Inbox 看到 → 点「AI 草稿」→ DeepSeek + RAG 检索 → 生成草稿 → 人工审核 → Send

  Chat 模式 (Phase 21 刚搭好框架):
    客户在 Portal 发消息 → WebSocket 实时推送到 Inbox → 人工手动回复
    ❌ 没有 AI 草稿按钮
    ❌ 没有自动回复

  你要的两层架构

  客户发消息
      ↓
  [AI 判断复杂度]
      ↓
  ┌─ 简单 ────────────────────────────┐   ┌─ 复杂 ───────────────────────────┐
  │ AI 直接回复 (auto-send)            │   │ AI 生成草稿 → 人工审核 → 发送     │
  │ 适用: "价格多少" "支持哪些渠道"      │   │ 适用: "我们需要评估后决定"          │
  │       "怎么开通试用"               │   │       "能否针对我们的场景定制"      │
  │ RAG 高置信度 + KB 有明确答案       │   │ RAG 低置信度 / 无匹配 / 含谈判信号  │
  └────────────────────────────────────┘   └──────────────────────────────────┘

  复杂度判断逻辑 — 4 种方案对比

  ┌───────────────────┬───────────────────────────────────────────────────────────────────────────┬─────────────────────┬────────┬─────────────┐
  │       方案        │                                   逻辑                                    │        延迟         │ 准确度 │    成本     │
  ├───────────────────┼───────────────────────────────────────────────────────────────────────────┼─────────────────────┼────────┼─────────────┤
  │ A: RAG 置信度阈值 │ 检索 top-1 score ≥ 0.85 → 简单, < 0.85 → 复杂。复用已有的 Confidence Gate │ 零额外              │ 80%    │ $0          │
  ├───────────────────┼───────────────────────────────────────────────────────────────────────────┼─────────────────────┼────────┼─────────────┤
  │ B: LLM 分类       │ 加一次 DeepSeek 调用判断复杂度 (few-shot prompt)                          │ +500ms              │ 95%    │ $0.001/call │
  ├───────────────────┼───────────────────────────────────────────────────────────────────────────┼─────────────────────┼────────┼─────────────┤
  │ C: 关键词规则     │ 正则匹配: 问价格/功能/流程 → 简单, 含"考虑/评估/商量/定制"→ 复杂          │ 零                  │ 70%    │ $0          │
  ├───────────────────┼───────────────────────────────────────────────────────────────────────────┼─────────────────────┼────────┼─────────────┤
  │ D: 混合 (推荐)    │ 先用 C 快速过滤明显简单的, 再用 A 查 RAG 分数, 不确定的走 B               │ 多数零, 少数 +500ms │ 90%+   │ 极低        │
  └───────────────────┴───────────────────────────────────────────────────────────────────────────┴─────────────────────┴────────┴─────────────┘

  推荐方案 D。理由：关键词规则零成本覆盖了 60% 的简单/复杂判断（"价格是多少" 明显简单、"我们内部评估一下" 明显复杂），剩下的交给 RAG 置信度，最后极少数 LLM 兜底。

  实现路径

  Phase 21a — AI 草稿 (1 天, 立即可用):
    在 ChatWindow 底部加「AI 草稿」按钮
    → 调用已有 ai-draft API (RAG 检索 + DeepSeek)
    → 生成草稿填入输入框 (像 Email 模式一样)
    → 人工点 Send 发出
    不改后端, 纯前端改动

  Phase 21b — 自动回复引擎 (3 天):
    新增: packages/ai-core/src/auto-reply.ts
    ├── classifyComplexity(message, kbContext) → "simple" | "complex"
    │    先用关键词规则, 再看 RAG score, 最后 LLM 兜底
    ├── autoReply(message, conversation, agent) → { reply, confidence, autoSent }
    │    简单 → compose + 自动 send + 标记 aiMetadata.autoSent=true
    │    复杂 → compose → 通知 Agent (WebSocket push) → 等审批
    └── Socket.IO 事件: "ai-draft-ready" (推送给 Agent 端)

    ChatWindow 改造:
    ├── 客户发消息 → Socket emit "message"
    ├── Server 收到 → classifyComplexity()
    │     ├── simple → autoReply() → auto-send → broadcast 回复
    │     └── complex → autoReply() → ai-draft-ready 事件 → Agent 看到预览
    └── Agent 端 ChatWindow: 复杂消息显示 "AI 已生成草稿, 请审核"
